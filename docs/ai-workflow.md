# M0：reasoning_effort 实验记录

比较相同问题在 `minimal`、`low`、`medium`、`high` 四档推理强度下的 token 用量、耗时和回答质量。

## 实验问题

- **embedding**：用一句话解释什么是 embedding。
- **奥克兰涨租**：我在奥克兰租房，房东 8 个月前涨过租金，现在又通知要涨，合法吗？

## 运行方式

在项目根目录执行：

```bash
uv run python -m kiwi_ask.m0_reasoning
```

## 实验结果

数据来自本次提供的终端运行记录：每个问题按 `minimal → low → medium → high` 顺序各调用一次，共八次。所有请求的 `finish_reason` 均为 `stop`，未报告因 token 上限而截断。下表质量评价由助手根据完整回答整理。

### 记录口径

- 推理 token：脚本输出中的 `reasoning`。
- 输出 token：脚本输出中的 `completion`，包含推理 token；可见回答 token 对应 `visible = completion - reasoning`，不要重复相加。
- 耗时：脚本输出中的 `time`，单位为秒，包含认证、网络和服务响应时间。
- 回答质量：根据完整回答判断准确性、指令遵循和对缺失条件的处理，不以篇幅长短代替质量。
- 同时检查 `finish_reason`；若回答被截断，应单独注明，不能直接与完整回答比较。

本次 embedding 问题每次输入为 14 tokens，可见回答按四档顺序为 52、63、64、73 tokens；涨租问题每次输入为 33 tokens，可见回答为 952、580、680、632 tokens。原始记录末尾另一次 `uv run kiwi-ask` 的回答未包含 effort 和用量，不计入这八组比较。

## 回答质量的核对依据

embedding 的四个回答都表达了向量表示和相似性的核心概念，也都遵守一句话要求。`low`、`medium`、`high` 使用“低维”描述常见做法，但低维不是所有 embedding 的必要定义条件；本题未观察到随 effort 增加而明显改善的回答质量。

涨租题按普通住宅租赁、未提供特殊涨租情形来评估。截至 2026-11-08 核对的 [Tenancy Services 官方说明](https://www.tenancy.govt.nz/rent-bond-and-bills/rent/increasing-rent/)：

- 通常需自租赁开始及上次涨租生效起满 12 个月，才能让新涨租生效；固定期限租约还需允许期间涨租。
- 普通住宅租赁通常至少提前 60 天书面通知，通知需写明新租金和生效日期。
- 通知可以在满 12 个月之前发出。因此，“8 个月前涨过，现在又通知”本身不足以判断违法，应核对上次涨租及本次涨租的生效日期。
- 特定改善房屋、增加服务或变更租约使租客受益等情形，可能适用例外；题目未提供这些信息。

据此，合格回答应说明通常适用的 12 个月规则，并追问本次涨租何时生效。如果现在就生效且无适用例外，通常不符合间隔要求；若现在通知、满 12 个月后才生效，则还需检查通知和租约条件。四档回答均未准确说明这一核心规则，因此都未通过本题事实准确性检查。

## 观察与结论

1. **简单问题增加推理用量，未见明显质量收益。** embedding 的推理 token 从 0 增至 256，输出总 token 从 52 增至 329，约为原来的 6.33 倍；四档回答均能完成任务。就本轮样本而言，minimal 已足够。
2. **耗时没有随 effort 严格递增。** embedding 中 medium 最快（2.46 s），minimal 反而最慢（4.36 s）；涨租题 low（7.90 s）也略快于 minimal（8.05 s）。首次认证、连接建立、网络或服务波动都可能影响耗时，本记录无法确定具体原因。
3. **更多推理没有纠正本题的知识错误。** 涨租题 high 的推理 token 达到 4224，输出总 token 是 minimal 的约 5.10 倍，耗时约为其 3.85 倍，却仍使用错误的 180 天规则。回答更详细、语气更确定，不等于事实更准确。
4. **可见回答长度与推理用量是不同指标。** 涨租题 minimal 的可见回答最长（952 tokens），high 为 632 tokens；high 的输出总量更大，主要来自内部推理。
5. **对 kiwi-ask 的后续启示。** 公共服务问答应优先接入可核验的官方资料，并检查日期、适用条件和引用。后续可以用相同问题做“无参考资料 / 提供官方资料”的对照实验，检验检索增强是否改善事实准确性，而不是只提高 effort。

以上仅反映两个问题、每组一次调用，不能推广为模型整体表现或稳定的耗时排序。脚本未接入检索，涨租题同时考查知识准确性和条件判断，不能把失败单独归因于推理能力。下一轮可在固定其他条件的前提下，每组重复 3–5 次、打乱 effort 顺序，比较用量与耗时的中位数，并按相同标准评价回答质量。
